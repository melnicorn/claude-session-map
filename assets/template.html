How it's measured

Everything comes from the transcript files Claude Code keeps on disk: one for each session and one for each subagent, with every event timestamped when it was written.

Main session working time adds up the gaps between events while Claude was mid-turn. Gaps that end in your next message count as waiting on you. Gaps that end with a subagent reporting back, or a message from another session, count as waiting too. Any single gap over 15 minutes counts as idle. Subagent working time adds up stretches of activity, and a pause over 10 minutes (a rate limit, say) splits the line.

Making maps isn't counted. A turn that runs /session-map (or asks for a map in words) is left out from that point to the end of the turn: its time, cost, tool calls and milestones. It shows on the main line as a dashed outline. Build with --include-map-work to count it.

Linked sessions are sessions this one started, sent messages to, or received messages from. They're drawn only for the part of their life that overlaps this session.

Cost prices every API response at list prices from : input, 5-minute and 1-hour cache writes, cache reads and output, per model. On a Claude subscription it shows what the same work would cost on the API, not what you paid.

Milestones: a commit is a git commit that succeeded; a test run is a recognised test command, marked failed when it exited with an error. PRs come from gh pr create and the app's PR links; artifacts are successful publishes.

The horizontal axis is scaled to working time. Quiet stretches shrink to a short break labelled with the time skipped. Timestamps mark when events were written, so model thinking time and slow tool calls count as working.
